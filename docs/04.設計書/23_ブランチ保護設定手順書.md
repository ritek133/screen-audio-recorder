# ブランチ保護設定手順書

## 1. 目的

`main` ブランチを保護し、PR 経由・レビュー承認・CI パスを必須とする開発フローを強制するための、GitHub リポジトリ設定手順を定める。

この設定は GitHub Actions のワークフローファイル（`ci.yml` / `release.yml`）では制御できず、リポジトリの **Settings** で手動設定する必要がある。本手順書はその手動設定を漏れなく行うためのチェックリストとして使用する。

対応要件: BR-1（main への直接 push 禁止）、BR-2（承認必須）、BR-3（CI パス必須）、BR-4（ステータスチェック登録）

---

## 2. 前提条件

- リポジトリの管理者（Admin）権限を持っていること
- CI ワークフロー（`.github/workflows/ci.yml`）が **1 回以上実行済み**であること
  - ステータスチェックの候補（`test`・`security`）は、CI が一度でも実行された後でないと選択リストに表示されない
  - 未実行の場合は、先にテスト用のブランチから `main` 向け PR を作成し、CI を起動させておく

---

## 3. 設定手順

### 3.1 ブランチ保護ルールの作成

1. GitHub リポジトリのページを開く
2. **Settings** → 左メニューの **Branches** を開く
3. **Branch protection rules** セクションの **Add branch protection rule**（または **Add rule**）をクリック
4. **Branch name pattern** に `main` と入力する

### 3.2 有効化する項目

作成したルールで以下のチェックボックスを有効化する。

| # | 設定項目 | 対応要件 | 内容 |
|---|---------|---------|------|
| 1 | ☑ Require a pull request before merging | BR-1 | `main` への直接 push を禁止し、PR 経由でのみ変更可能にする |
| 2 | └ ☑ Require approvals（承認数: **1**） | BR-2 | マージ前に最低 1 名のレビュー承認を必須とする |
| 3 | ☑ Require status checks to pass before merging | BR-3 | CI がパスしていないとマージ不可にする |
| 4 | └ ☑ Require branches to be up to date before merging | BR-3 | マージ前にブランチを最新の `main` に追従させることを必須とする |
| 5 | └ Status checks（必須チェックの選択）: `test` | BR-4 | `ci.yml` のテストジョブ名 |
| 6 | └ Status checks（必須チェックの選択）: `security` | BR-4 | `ci.yml` のセキュリティチェックジョブ名 |

> 補足: オーナー・管理者にもルールを強制したい場合は **Do not allow bypassing the above settings** を有効化する（任意）。

### 3.3 保存

- ページ下部の **Create**（新規作成時）または **Save changes**（既存ルール編集時）をクリックして確定する

---

## 4. ステータスチェック名に関する重要な注意点

ステータスチェックとして登録する名前は、`ci.yml` で定義された **ジョブ名と完全に一致**していなければならない。名前が一致しないと、そのチェックは「必須」として機能せず、CI が実行されていないのにマージできてしまう。

- 登録するステータスチェック名: `test`、`security`
- これらは `.github/workflows/ci.yml` のジョブ名（`jobs:` 直下のキー）と一致する
  - `test` … pytest を実行するテストジョブ
  - `security` … gitleaks + カスタムスクリプトによるセキュリティチェックジョブ

`ci.yml` 側でジョブ名を変更した場合は、本設定のステータスチェック名も同じ名前へ更新すること。片方だけ変更すると保護が実質無効化されるため注意する。

---

## 5. 設定後の確認

- テスト用のブランチから `main` 向けに PR を作成し、以下を確認する:
  - `test`・`security` の両チェックが起動し、両方がパスするまでマージボタンが有効化されないこと
  - レビュー承認が 1 件付くまでマージできないこと
  - `main` へ直接 push しようとすると拒否されること
