# ADR-001: GUI レイアウト改善（小型モニター対応）

## ステータス

決定済み（Accepted）

## 日付

2026-08-01

## コンテキスト

現在の GUI は `root.minsize(800, 600)` の固定サイズで設計されており、
小型モニター（1366x768 以下）では以下の問題が発生する：

- ウィンドウが画面に対して大きすぎ、操作しづらい
- フォントサイズが固定（10pt）で、高 DPI 小型モニターでは文字が小さい
- Treeview のカラム幅が固定値（合計 680px）で、小型画面でははみ出す
- 3ペイン（一覧/要約/全文）が縦並びのため、縦方向のスペースが不足
- padding/margin が固定で、小型モニターではスペースの無駄が目立つ

## 検討案

### 案1: コンパクトモード

- `root.minsize(640, 480)` に縮小
- コントロールパネルを1行に凝縮
- ttk.Style で全体フォントを 9pt に統一
- Treeview 行高さを 24px → 22px に縮小
- padding を 8 → 4 に削減
- 要約/全文ペインを横並びに変更

**メリット:**
- 変更量が少ない（既存コードの微調整のみ）
- 小型モニターでの使いやすさが大幅向上
- 大型モニターでも違和感なし

**デメリット:**
- フォントが小さくなるため、視力が弱いユーザーには不向き

### 案2: DPI 自動スケーリング

- 画面サイズを検出して UI 要素のスケール係数を自動決定
- 小型（≤768px）: scale=0.8、標準（≤1080px）: scale=1.0、大型: scale=1.2
- フォントサイズ、padding、カラム幅にスケールを適用

**メリット:**
- ユーザーの環境に自動適応
- 設定不要

**デメリット:**
- 実装が複雑（全 UI コンポーネントにスケール適用が必要）
- エッジケースでレイアウト崩れの可能性

### 案3: 2ペイン横並びレイアウト

- 録画タブを左右2ペイン構成に変更
  - 左: メモ一覧（Treeview、日時+テーマのみ）
  - 右: 要約 + 全文（縦積み）
- PanedWindow (HORIZONTAL) でドラッグリサイズ可能

**メリット:**
- 縦方向のスペースを最大限活用
- 一覧と詳細を同時に閲覧できる
- ドラッグで比率を自由に調整可能

**デメリット:**
- レイアウトの大幅変更（既存テストへの影響あり）
- 横幅が狭い場合は逆に見づらくなる可能性

### 案4: フォントサイズ設定機能

- 「詳細設定」タブにフォントサイズ選択（小/中/大）を追加
- 選択に応じて全ウィジェットのフォントサイズを動的変更
- 設定は AppSettings に保存して次回起動時に反映

**メリット:**
- ユーザーが自分の環境に合わせて調整可能
- 視力に合わせた最適化ができる

**デメリット:**
- 設定項目が増える（ユーザー負担）
- フォント変更時のレイアウト再計算が必要

### 案5: 全部入り（案1 + 案2 + 案3）

- コンパクト化 + 自動スケーリング + 2ペインレイアウト
- 最も高い改善効果が見込めるが、工数も最大

## サンプル画面

各案のモックアップは `gui_samples.py` で確認可能：

```bash
python gui_samples.py
```

タブ切り替えで以下を比較できる：
- 現在のレイアウト
- 案1: コンパクトモード
- 案3: 2ペイン横並びレイアウト
- 案4: 大きめフォント（視認性重視）

## 決定

**案3: 2ペイン横並びレイアウト** を採用する。

理由：
- 縦方向のスペースを最大限活用でき、小型モニターでの視認性が大きく向上
- 一覧と詳細を同時に閲覧でき、操作効率が良い
- PanedWindow によるドラッグリサイズで、ユーザーが自由に比率を調整可能
- コントロールパネルは1行に凝縮して省スペース化
