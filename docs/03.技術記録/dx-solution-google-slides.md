## スライド3: 目的

**業務記録を人手依存から脱却し、再利用可能なデータへ変える**

- 録画、録音、議事メモ作成にかかる時間を削減する
- 発言内容や操作内容の記録漏れを防止する
- 会議後の要約、整理、共有までを短時間で完了させる
- 個人PC上でも利用可能な構成にし、導入ハードルを下げる
- 蓄積した記録をナレッジとして横展開できる状態を作る

ひとこと:
- 単なる録画ツールではなく、業務記録の標準化基盤を目指す

---

## スライド4: 解決課題

**現状の課題**

- 会議や作業記録が担当者ごとにバラつく
- 議事録作成に時間がかかり、共有まで遅れる
- 重要な発言や操作手順の抜け漏れが発生する
- 過去記録を検索しにくく、再利用できない
- クラウド利用が難しい環境ではAI活用が進みにくい

**提案後の改善イメージ**

- 収録から文字起こし、要点整理までを自動化
- 記録品質を標準化し、属人化を抑制
- ローカルLLMまたはAPI連携で環境に応じた運用が可能
- メモ一覧化により、振り返りとナレッジ検索を容易化

---

## スライド5: アーキテクチャ

**システム構成**

1. ユーザーがPCアプリで録画対象と録音対象を選択
2. 画面キャプチャと音声キャプチャを同時に取得
3. 録画データを動画ファイルとして保存
4. 音声データをWhisperで文字起こし
5. 必要に応じてLLMで要約、整形、トピック抽出
6. メモ一覧として保存し、後続業務で再利用

**構成要素**

- UI層: 録画設定、開始停止、メモ参照
- 収集層: 画面キャプチャ、マイク/システム音声取得
- 変換層: エンコード、音声文字起こし
- 活用層: 要約、整形、テーマ抽出、履歴管理
- 保存層: 動画ファイル、音声ファイル、メタデータ、メモ

図に入れる文言例:

- Screen Capture
- Audio Capture
- Transcriber
- LLM Processor
- Memo Store

## スライド7: 非機能要件

**性能**

- 録画中に大きな操作遅延が発生しないこと
- 一般的な業務PCで動作可能であること
- 長時間録画でも安定して保存できること

**可用性 / 信頼性**

- 収録失敗時に原因を把握できること
- 保存途中の異常でも影響範囲を最小化すること
- ログやエラー通知により復旧しやすいこと

**セキュリティ**

- ローカル保存を前提とし、機密情報を社外へ送信しない構成を選択可能
- ローカルLLM利用により閉域運用にも対応可能
- API利用時は接続先、鍵管理、送信範囲を制御可能

**保守性 / 拡張性**

- 録画、文字起こし、LLM処理を疎結合にする
- モデル切替や保存先変更に対応しやすい設計
- 将来の業務システム連携を見据えた構成

## スライド8: DFD

**DFD レベル0**

```text
[利用者]
   |
   | 録画指示 / 設定
   v
(現場記録DXアプリ)
   |\
   | \ 録画ファイル
   |  ------> [動画保存領域]
   |
   | 音声データ
   v
(文字起こし処理)
   |
   | テキスト
   v
(要約・整形処理)
   |\
   | \ メモ情報
   |  ------> [メモ保存領域]
   |
   ------> [利用者]
           要約結果 / メモ一覧
```

**説明ポイント**

- 外部エンティティは利用者
- 主処理は「収録」「文字起こし」「要約・整形」
- データストアは「動画保存領域」「メモ保存領域」
- 出力は録画ファイルだけでなく、再利用可能なテキスト資産
