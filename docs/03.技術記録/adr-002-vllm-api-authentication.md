# ADR-002: vLLM API の認証認可

## ステータス

提案中（Proposed）

## 日付

2026-08-08

## コンテキスト

デスクトップアプリから vLLM サーバー（EC2 上の Whisper + LLM）への通信において、
現在は**セキュリティグループ（CIDR ベース）でのネットワーク制限のみ**で API レベルの認証がない。

この状態では以下のリスクがある：

- VPC 内の他のリソースが侵害された場合、vLLM API に無制限アクセスされる
- API エンドポイントに到達できれば誰でもリクエスト可能
- ユーザー識別・利用量追跡ができない
- 将来的にインターネット経由でアクセスする場合に対応できない

## 検討案

### 案1: vLLM の `--api-key` オプション

vLLM サーバー起動時に `--api-key` を指定し、クライアントは `Authorization: Bearer <key>` で認証する。

```
[デスクトップアプリ] ── Bearer token ──→ [EC2 vLLM :8000/:8001]
```

**メリット:**
- 実装が最も簡単（docker-compose の command に1行追加）
- アプリ側は既存の `api_key` フィールドをそのまま使用可能（`llm_client.py` 対応済み）
- 追加インフラ不要、追加コスト $0
- セキュリティグループとの二重防御

**デメリット:**
- トークンが固定（有効期限なし）。漏洩時は手動ローテーション
- HTTPS 非対応（通信は平文 HTTP）
- 複数ユーザーに異なるキーを発行できない
- レート制限・アクセスログなし

### 案2: Nginx リバースプロキシ + Bearer トークン

EC2 内に Nginx を追加し、HTTPS 終端 + トークン検証を行う。vLLM は localhost のみ listen。

```
[デスクトップアプリ] ── HTTPS + Bearer ──→ [Nginx :443] ──→ [vLLM :8000/:8001]
```

**メリット:**
- HTTPS による通信暗号化
- 複数トークンの管理が可能（nginx 設定で複数キー定義）
- レート制限（`limit_req`）、アクセスログ取得可能
- vLLM を外部から隠蔽できる

**デメリット:**
- Nginx コンテナの追加管理が必要
- SSL 証明書の取得・更新が必要（自己署名 or Let's Encrypt）
- ユーザー管理は手動（設定ファイルベース）
- トークンは依然として固定（有効期限なし）

### 案3: API Gateway (HTTP API) + Cognito + VPC Link

AWS マネージドサービスで認証認可を実現する。Cognito でユーザー管理し、API Gateway がJWT 検証する。

```
[デスクトップアプリ] ── ログイン ──→ [Cognito User Pool]
                                          │
                                     JWT 発行
                                          │
[デスクトップアプリ] ── JWT ──→ [API Gateway HTTP API] ── VPC Link ──→ [EC2 vLLM]
```

**メリット:**
- ユーザー管理（登録・パスワード変更・無効化）が Cognito で完結
- JWT トークンに有効期限あり（デフォルト1時間）。漏洩しても自動失効
- HTTPS 自動対応（API Gateway）
- ユーザー別のアクセスログ（JWT にユーザー ID 含む）
- MFA（多要素認証）オプション対応
- NLB/ALB 不要（HTTP API + VPC Link で EC2 に直接接続）
- 使わない時は課金 $0（リクエスト課金: $1.00/100万リクエスト）

**デメリット:**
- 構成が最も複雑（Cognito + API Gateway + VPC Link）
- アプリ側にログイン画面の追加が必要
- API Gateway のタイムアウト上限 30 秒（長時間推論に制約）
- API Gateway のペイロード上限 10MB（大きな音声ファイル直接送信に制約）
- Cognito の学習コスト

## 制約事項の整理

### タイムアウト・ペイロードの影響

| ユースケース | 典型的な所要時間 | データサイズ | 案1 | 案2 | 案3 |
|------------|--------------|-----------|-----|-----|-----|
| LLM テキスト修正（短文） | 2〜5 秒 | < 1KB | ✓ | ✓ | ✓ |
| LLM 要約生成 | 5〜15 秒 | < 10KB | ✓ | ✓ | ✓ |
| Whisper 文字起こし（1分音声） | 10〜20 秒 | ~1MB | ✓ | ✓ | ✓ |
| Whisper 文字起こし（5分音声） | 30〜60 秒 | ~5MB | ✓ | ✓ | ⚠️ タイムアウト |
| Whisper 文字起こし（10分音声） | 60〜120 秒 | ~10MB | ✓ | ✓ | ✗ タイムアウト+サイズ |

## 影響範囲

### 案1 の場合
- `infra/templates/11_vllm-server.yaml`（`--api-key` パラメータ追加）
- アプリ側変更なし（既存の `api_key` フィールドを使用）

### 案2 の場合
- `infra/templates/11_vllm-server.yaml`（Nginx コンテナ追加、ポート変更）
- アプリ側変更なし（エンドポイント URL を HTTPS に変更するのみ）

### 案3 の場合
- `infra/templates/13_api-gateway.yaml`（新規: API Gateway + Cognito + VPC Link）
- `infra/templates/11_vllm-server.yaml`（SG 変更: API Gateway からのみ許可）
- `src/screen_audio_recorder/cognito_auth.py`（新規: Cognito ログイン処理）
- `src/screen_audio_recorder/gui/login_dialog.py`（新規: ログイン画面）
- `src/screen_audio_recorder/llm_client.py`（JWT トークン付与に変更）
- `src/screen_audio_recorder/models.py`（認証設定モデル追加）
- `src/screen_audio_recorder/llm_settings_store.py`（認証設定の保存）
