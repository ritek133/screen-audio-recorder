# Git ワークフロー規約

コード修正・機能追加・ドキュメント変更など、リポジトリ内のファイルを変更する作業では、必ず以下の順序を守ること。

## 着手前の必須手順（この順序を厳守）

1. **main を最新化する**
   - `git checkout main`
   - `git pull origin main`
2. **作業ブランチを作成する**
   - `git checkout -b <type>/<短い説明>`
   - ブランチ名は英語・ハイフン区切り・2〜4単語
3. **作業ブランチ上でファイルを編集する**

**重要**: main / master ブランチ上で直接ファイルを編集・コミットしてはならない。
必ずブランチを作成してから編集を開始すること。

## ブランチ名のプレフィックス

| 作業種別 | プレフィックス | 例 |
|----------|----------------|-----|
| バグ修正 | `fix/` | `fix/updater-backup-file-lock` |
| 機能追加 | `feature/` | `feature/audio-device-selector` |
| リファクタリング | `refactor/` | `refactor/split-recorder-controller` |
| ドキュメント | `docs/` | `docs/update-user-manual` |
| その他雑務 | `chore/` | `chore/bump-dependencies` |

## 実装順序の原則

- ユーザーから「修正して」「追加して」と依頼されても、**まず main 最新化 → ブランチ作成を先に行う**。
- ブランチを切る前にファイルを編集しない。編集は必ずブランチ作成後。
- 順序に不明点があれば、編集を始める前にユーザーへ確認する。

## コミット・プッシュ

- コミットはユーザーが明示的に指示したときのみ行う。
- main / master への直接コミットは禁止（pre-commit フックでも拒否される）。
- プッシュは新しいブランチに対して行い、main へ直接プッシュしない。

## フックによる強制

以下のフックがこの規約を補強している。矛盾する挙動をしないこと。

- `.kiro/hooks/block-edit-on-main.json`（PreToolUse）: main/master 上での編集系ツール実行をブロックする。
- `.git/hooks/pre-commit`: main/master への直接コミットを拒否する。

## 注意（フックの整合性）

セッション開始時に複数のブランチ作成フック（`branch-*.json`）が同時に発火し、
互いに矛盾する指示（chore/docs/feature/fix/refactor を同時に要求）を出すことがある。
その場合は、ユーザーの実際の依頼内容に対応する 1 つの作業種別だけを選び、
本規約の順序（main 最新化 → ブランチ作成 → 編集）に従うこと。
